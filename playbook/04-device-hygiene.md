# 阶段 04：设备治理（把本机收拾干净）

> 网络层干净了，本机还是脏的：旧代理客户端的残留、系统时区不对、浏览器报中文——这些都是风控眼里的矛盾信号。
> 这一阶段只做**运营机**（建议 macOS）上的清理与设置，不碰路由器和 VPS。
> 执行模式：命令行能做的你（AI）直接做、自己验收；图形界面操作（系统设置面板、浏览器设置、
> 官方卸载器、iPhone）必须用户出手——你给出清单式请求：要做什么、怎么做、做完说什么。
> 本阶段无 ⛔高危步骤，但删除类操作动手前先把要删的内容给用户看一眼。

## 本阶段目标

- 系统时区对齐目标地区；浏览器语言 en-US（系统语言不强改）
- 本机代理/VPN 残留清零：客户端、LaunchDaemon、系统扩展、系统代理设置、环境变量，全部扫出来清干净
- Wi-Fi 记忆清零：运营机只记得路由器这一个网络
- 浏览器分平台隔离，逐个关 WebRTC；不开 resistFingerprinting
- 治理完成后复验：残留扫描干净 + 03 相关项回测全绿

## 前置条件

- [ ] 阶段 03 已跑过一遍（允许时区/语言/WebRTC 项 FAIL——那正是本阶段要修的）
- [ ] 脚本已复制到 `~/overseas-ops/bin/`（03 前置条件里做过）
- [ ] 先问用户一次：哪些软件**不能删**——公司强制要求的 VPN（如 AnyConnect）、工作必需的远程工具。
      这些保留，但要让用户知道它们的存在就是风险项，运营账号操作期间不要打开

## 步骤

### 4.1 系统时区改到目标地区

**为什么**：浏览器报告的时区来自操作系统。IP 在美国西部、系统时区在北京，是 03 阶段第 4 项的直接 FAIL 原因。

你直接执行，先记录当前时区（回滚要用），再改成住宅 IP 所在地区的时区：

```bash
systemsetup -gettimezone                                   # 记下原值，存进 ~/overseas-ops/
sudo systemsetup -settimezone America/Los_Angeles         # 按目标地区替换
systemsetup -gettimezone                                   # 确认已生效
```

常用目标：`America/Los_Angeles`（美西）、`America/New_York`（美东）、`Europe/London`（英国）。
sudo 需要密码时，让用户在终端里输一次。

**PASS 标准**：`systemsetup -gettimezone` 输出目标时区；重启浏览器后 browserleaks.com/javascript 的时区行与之一致。

> 注意保持系统时间自动同步（系统设置 → 通用 → 日期与时间——这一步是图形操作，让用户顺手确认一眼），时区对了但钟差太大同样是矛盾信号。

### 4.2 语言策略：浏览器必须改，系统语言不强改

**为什么**：平台看语言有两个通道——浏览器的 `Accept-Language`/`navigator.language`（强信号，必须改）和操作系统语言（弱信号，且这台机器用户可能还要日常用）。

**浏览器（必须用户出手，每个运营浏览器都要做）**：给用户清单式请求——

- [ ] 打开浏览器设置，把语言改为 **English (United States)**
- [ ] **移除语言列表里的中文**
- [ ] 重启浏览器
- [ ] 做完回你"已改"

**系统语言：不强改**。两种情况：

- 这台 Mac 是专用运营机（或建了专用运营用户，见 4.7）：可以把该用户的系统语言设为 English
- 这台 Mac 还兼顾用户的中文日常使用：**保持中文系统语言不动**。不为了伪装把既有画像连根拔起——一台"美国人的电脑"装的全是中文软件、中文文件名，这种违和感比系统语言本身更扎眼。浏览器语言改对即可

**PASS 标准**：用户改完后你复核——browserleaks.com/javascript 显示 `Accept-Language: en-US`、无 `zh-CN`（即 03 第 5 项转绿）。

### 4.3 代理/VPN 残留清零

**为什么**：这是本阶段最重要的一步。以前装过的 ClashX、v2rayN、Tailscale、公司 VPN、抓包工具……它们的残留（后台进程、LaunchDaemon、系统扩展、系统代理设置、环境变量）有两个危害：一是可能绕过路由器透明接管，造成"半通"或直连泄露；二是设备上存在一堆翻墙工具本身就是环境矛盾。透明接管方案下，**本机一个代理客户端都不该有**。

你先跑只读扫描（不改任何东西，只报告）：

```bash
~/overseas-ops/bin/proxy-residue-scan.sh
```

对扫描报告里的每个 FAIL 项，按性质清理——**命令行能清的你直接清，图形界面的列成清单请用户做**：

| 残留类型 | 清理方法 | 谁做 |
|---------|---------|------|
| 代理/VPN 客户端 App | 用**官方卸载器**卸载（没有卸载器的拖到废纸篓），别只删 .app 留半残 | 用户（你给清单：卸载哪些、卸载器在哪） |
| LaunchDaemon / LaunchAgent | `sudo launchctl bootout system <plist路径>` 后删除 plist 文件（LaunchAgent 用 `launchctl bootout gui/$(id -u) <路径>`） | 你直接执行 |
| 系统扩展 / 网络扩展 | 系统设置 → 通用 → 登录项与扩展 → 网络扩展，关闭并移除；顽固的用 `systemextensionsctl uninstall <TeamID> <bundleID>` | 面板操作用户做；`systemextensionsctl` 你执行 |
| VPN 配置 | 系统设置 → VPN，删除全部配置 | 用户（清单：删哪些） |
| 系统代理 | 系统设置 → Wi-Fi → 详细信息 → 代理，全部开关关掉（扫描脚本会验证 `scutil --proxy` 全 0） | 用户（清单）；你跑 `scutil --proxy` 复核 |
| shell 环境变量 | 编辑 `~/.zshrc` 等文件，删掉 `http_proxy`/`https_proxy`/`all_proxy` 相关行（扫描报告只给文件名+行号，你核对后再删） | 你直接改，删前把要删的行给用户看一眼 |
| 配置目录残留 | `~/Library/Application Support/` 下的 ClashX、Surge、V2rayU 等目录直接删除 | 你直接删，删前列出清单 |

**PASS 标准**：清完后你再跑一次 `proxy-residue-scan.sh`，输出 `RESULT: PASS`（WARN 项允许存在，但每一条都要和用户确认它是什么、为什么保留——比如公司 VPN）。

> 同一轮清理做完建议让用户重启一次 Mac 再复扫：有些 LaunchDaemon 要重启后才彻底消失。

### 4.4 Wi-Fi 记忆清零

**为什么**：运营机误连手机热点或公共 WiFi = 直接裸奔（透明接管只在路由器上）。从源头杜绝：让这台机器只认识路由器。

必须用户出手（图形操作），给清单：

- [ ] 系统设置 → Wi-Fi → 已知网络：除路由器 SSID 外**全部忘记**
- [ ] 把"询问是否加入热点/新网络"关掉
- [ ] iPhone 运营机同样处理：只连路由器 WiFi；并在该网络详情里关闭"私有无线局域网地址轮换"（设为固定）、关闭"限制 IP 地址跟踪"、关闭 iCloud 专用代理（Private Relay）——这些苹果隐私功能会绕过隧道
- [ ] 做完回你"已清"

**PASS 标准**：用户确认已知网络列表只剩路由器一个；你让他断开重连一次，自动回的也是路由器。

### 4.5 浏览器分平台隔离 + 关 WebRTC

**为什么**：同一浏览器同时登 Google 系和 X 和 TikTok，等于主动告诉平台"这些账号是同一个人"。用不同浏览器做天然隔离，每个浏览器只碰自己的平台。

默认分配（可按需调整，但一个浏览器只服务一个平台族）：

| 浏览器 | 平台 |
|--------|------|
| Chrome | Google 系（YouTube / Gmail） |
| Firefox | X（Twitter） |
| Edge | TikTok |
| Brave | Meta 系（Instagram / Facebook） |

每个浏览器统一做四件事（1 已由 4.2 完成；2/3/4 是图形操作，给用户一份合并清单，按浏览器逐项列清）：

1. 语言 English (US)（4.2 已做）
2. 主页或新标签页设为 `ipleak.net`——每次打开浏览器第一眼就能确认出口对不对
3. 外观主题互相区分开，避免手滑登错账号
4. **关 WebRTC**：
   - Firefox：`about:config` → `media.peerconnection.enabled` 改为 `false`（原生支持，最干净）
   - Chrome / Edge / Brave：没有官方开关，装一个可信的 WebRTC 控制类扩展（如 WebRTC Control），装完必须实测验证；不愿意装扩展的替代方案是：永不授权摄像头/麦克风 + 依赖路由器层接管，但要以实测为准

**PASS 标准**：用户做完后，你逐个浏览器打开 browserleaks.com/webrtc 实测，Local/Public IP 均不泄露本地与真实 IP（即 03 第 3 项在每个浏览器里各自转绿）。

### 4.6 明确不要做的事

这几条是你和用户都要遵守的纪律：

- **不开 `resistFingerprinting`**（Firefox 的防指纹开关）：它把指纹统一成"Tor 用户"模板——平台看到的是一个挂着美国家庭宽带 IP、指纹却是 Tor 的怪物，统一指纹反而显眼
- **不装来路不明的"防关联/指纹修改"插件**：指纹可以改，但改出来的指纹要和 IP、系统、行为全部自洽，普通用户做不到，只会制造更多矛盾
- 反指纹浏览器（Multilogin / AdsPower 这类）**不是默认项**：只在同平台多号、或平台明确给了风控信号时再考虑，那是另一个量级的工程
- **不用任何客户端代理 App 作为运营主链路**：主链路永远是路由器透明接管，本机代理只是 02 施工期的临时工具，验收完就该删掉（见 4.3）

### 4.7 （建议）专用运营 macOS 用户

如果这台 Mac 还承担用户的个人日常使用，强烈建议他建一个专用运营用户。这是图形操作，给清单式请求：

- [ ] 系统设置 → 用户与群组 → 新增一个**标准用户**（如 `ops`）
- [ ] 该用户内：系统语言 English、时区目标地区、不加中文输入法、深色壁纸 + 极简 Dock（肉眼一眼确认"我在运营用户里"）、只保存路由器 WiFi
- [ ] 运营活动全部在这个用户里进行；不用快速用户切换来回跳——进运营用户前先退出个人用户

它能带来：独立的 Cookie/会话/钥匙串/偏好设置，个人环境和运营环境互不污染。

### 4.8 治理后复验

全部清理完成后，你按顺序复验：

```bash
~/overseas-ops/bin/proxy-residue-scan.sh   # 期望 RESULT: PASS
~/overseas-ops/bin/net-check.sh            # 期望 RESULT: PASS
```

再回 03 阶段重跑三个浏览器项：WebRTC（3.4）、时区（3.5）、语言（3.6），以及每个运营浏览器的 ipleak.net 首页确认。

**PASS 标准**：两个脚本全 PASS + 浏览器四项全绿。此时环境达到"可以长期运营"的状态，给用户一句话播报。

## 回滚

- 时区：`sudo systemsetup -settimezone <4.1 记录的原值>`
- 浏览器语言/主题/主页：让用户在设置里改回即可
- 删除的代理/VPN 客户端：重新安装即可（但先想清楚为什么还要装回来——运营机上不该有）
- 忘记的 Wi-Fi：重新输入密码加入即可
- 残留扫描脚本本身只读，无副作用
- 如果清理后网络异常：99% 是误删了正常组件，先 `net-check.sh` 定位是哪一层断了，再按 `docs/recovery.md` 处理
